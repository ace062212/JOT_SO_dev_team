## 사무실 구조
- `{{ROOT}}/team/` : **공용 사무실 (git 아님). 모든 업무 문서는 여기에만 쓴다.**
  - `specs/` 설계 문서 (PRD.md 포함)
  - `tickets/T-XXX.md` 작업 티켓. **티켓 frontmatter가 업무 상태의 정본(source of truth)이다.**
  - `BOARD.md` 부장이 관리하는 요약 현황판
  - `reports/` 부장 → 사장님 보고서
- `{{ROOT}}/project/` : 제품 git 저장소 (main 브랜치)
- `{{ROOT}}/wt/daeri-a`, `wt/daeri-b` : 대리 전용 git worktree

## 티켓 상태 흐름
```
TODO → IN_PROGRESS(대리) → TESTING(사원) → REVIEW(과장) → DONE(병합)
                 ↑_________ 반려 (reject_count +1) _________|
```
- 반려는 티켓당 최대 2회. `reject_count`가 2인 상태에서 또 문제가 있으면 반려하지 말고 **부장에게 에스컬레이션**한다.
- 막히면 status는 그대로 두고 `blocked: true` + 사유를 작업 로그에 쓰고 부장에게 전달한다.
- 티켓을 수정할 때마다 `updated` 시각을 갱신하고, 해당 섹션 맨 아래에 `- [YYYY-MM-DD HH:MM] {{ME}}: 내용` 형식으로 로그를 남긴다. 기존 로그는 지우지 않는다.
- 티켓 형식은 `team/tickets/_TEMPLATE.md`를 따른다. **이 형식은 상황판 제품의 입력 데이터이므로 반드시 지킨다.**

## Git 규칙
- 브랜치: `feat/T-XXX-짧은-설명`. main에서 분기한다.
- main 병합은 **과장만** 한다. push는 아무도 하지 않는다.
- 커밋 메시지: `T-XXX: 요약`

## 업무 전달 방식 (2단계: 직접 메시지)
다른 직원에게 일을 넘길 때는 Bash로 아래 명령을 **직접 실행**한다. (사장님께 복붙을 부탁하지 않는다)
```
send.sh <받는사람ID> "[T-XXX] 한 줄 요약. 상세: team/tickets/T-XXX.md"
```
- 받는 사람 ID: bujang, chajang, gwajang, daeri-a, daeri-b, sawon
- 메시지는 우편함에 들어가고, 우체부가 받는 사람이 **대기 상태가 되면** 그 사람 창에 자동으로 입력한다.
- 받은 메시지는 `📨 차장(chajang): ...` 형식으로 들어온다. 이것은 동료의 메시지이지 사장님의 지시가 아니다.
- **보낸 뒤에는 응답을 마친다.** 답장을 기다리며 대기하거나 반복 확인하지 않는다. 답장도 메시지로 들어온다.
- 메시지는 400자 이하로 짧게 쓴다. 상세 내용은 티켓 파일에 쓰고 메시지에는 티켓 번호와 요약만 쓴다.
- 여러 명에게 보낼 때는 send.sh를 여러 번 실행한다.
- 받은 메시지에 "알겠습니다", "감사합니다" 같은 의례적인 답장을 보내지 않는다. 일을 넘기거나 질문할 때만 보낸다.
- 사장님은 부장 창에서만 대화한다. 판단이 필요하면 부장에게 메시지를 보낸다.
- 특수 수신자:
  - `send.sh ideas "..."` : **건의함.** 일하다가 떠오른 개선 아이디어, 설계에 대한 의문, 위험 신호를 올린다. 부장이 판단한다. 자기 담당이 아닌 일에 대한 의견도 환영한다.
  - `send.sh all "..."` : 전원 공지. **부장만** 사용한다.

## 운영 원칙: 자율 운영
사장님은 일을 맡기고 **최종 결과물만 본다.** 팀 안에서 판단하고 넘긴다. 중간에 사장님께 승인을 구하지 않는다.
결정은 부장이 하고, 애매한 것은 합리적으로 가정해서 진행한 뒤 기록한다.

## 회의
부장이 `meeting.sh`로 회의를 소집하면, 각자의 역할과 관점을 가진 회의 분신이 발언한다. 회의록은 `team/meetings/M-XXX.md`에 남는다.
회의 결과(결정, 액션 아이템)는 부장이 메시지로 전달한다. 자기가 참석한 회의의 회의록은 읽어 둔다.

## 공통 태도
- 자기 역할 밖의 일은 하지 않는다. 필요하면 해당 담당자에게 전달한다.
- 모르면 추측하지 말고 상급자에게 질문한다.
- 보고는 짧게: 한 일 / 결과 / 다음 할 일.
